Fluid Physics Approach

Three ways to make the liquid pour look and behave realistically in MagicSort

A — Matter.js + Metaballs

Matter.js handles rigid-body + particle physics; canvas renders them with a metaball (gaussian blur + threshold) pass so individual drops merge into a smooth liquid blob. Tube tilt uses the same engine — liquid actually sloshes inside as it rotates.

Pros

  • Looks genuinely liquid — blobs merge, split, coalesce
  • Real gravity, collisions, tube walls
  • Matter.js is well-maintained, 47 kB gzipped

Cons

  • Need to model tube as Matter.js body
  • Canvas overlay for metaball render pass
  • Medium integration effort (~3–4 days)

B — Custom SPH Fluid

Smoothed Particle Hydrodynamics: each color unit becomes a set of fluid particles with pressure and viscosity forces. Rendered as metaballs. No third-party engine — pure canvas math. Most realistic fluid behavior.

Pros

  • True fluid dynamics — cohesion, surface tension, flow
  • No dependency to manage
  • Full control over feel

Cons

  • CPU-intensive for many particles (needs spatial hash)
  • Hardest to implement correctly (~5–7 days)
  • Tuning can be tricky

C — Planck.js (Box2D) + Metaballs

Planck.js is a faithful JavaScript port of Box2D. More physically accurate than Matter.js for complex collisions and constraints. Same metaball rendering strategy. Good choice if you want the tube joints and constraints to feel very precise.

Pros

  • Most accurate rigid body physics
  • Active maintenance, TypeScript types
  • Great for constrained tube opening geometry

Cons

  • More verbose API than Matter.js
  • Larger learning curve
  • Box2D wasn't designed for fluid (same workaround as A)
